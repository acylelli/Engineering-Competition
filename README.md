# Engineering Competition

## Watch Safety

스마트워치 기반 고령자·인지저하 사용자 외출 안전 지원 시스템입니다. Wear OS의 센서와 GPS로 위험을 감지하고, 보호자 Android 앱과 백엔드 서버를 통해 위치 확인·SOS·안전구역·귀가 지원을 하나의 흐름으로 연결합니다.

## 서비스 구성

```text
Wear OS App ── 위치·안전 이벤트 ──> Backend ── Push·상태 ──> Guardian App
Wear OS App <── 귀가 요청·안전구역 ─ Backend <── 보호자 명령 ─ Guardian App
```

| 모듈 | 기술 | 핵심 책임 |
| --- | --- | --- |
| `wear-os-app` | Kotlin, Wear OS, Compose | 센서 수집, 낙상 감지, SOS, 위치, 귀가 안내 |
| `guardian-app` | Kotlin, Android, Compose | 지도, 안전구역, 긴급 알림, 귀가 요청, 이벤트 기록 |
| `backend` | Spring Boot, Kotlin/Java, MySQL, FCM | 연결 관리, 위치·이벤트 저장, Push 전달 |
| `docs` | Markdown | 기획, 아키텍처, API 계약, 데모 시나리오 |

## 핵심 사용자 흐름

### 낙상 및 자동 SOS

1. 워치가 가속도·자이로 기반 낙상 후보를 감지합니다.
2. 워치가 진동하고 사용자에게 상태를 확인합니다.
3. 사용자가 `도와주세요`를 선택하거나 일정 시간 무응답·저활동 상태가 지속되면 SOS를 생성합니다.
4. 워치가 현재 위치와 감지 근거를 서버로 전송합니다.
5. 서버가 이벤트를 저장하고 보호자 앱으로 긴급 Push를 전달합니다.

### 안전구역 이탈 및 귀가

1. 사용자가 등록 안전구역을 벗어납니다.
2. 워치와 보호자 앱에 이탈 경고가 전달됩니다.
3. 사용자 또는 보호자가 귀가 안내를 시작할 수 있습니다.
4. 집 안전구역에 재진입하면 안내를 종료하고 보호자에게 도착을 알립니다.

## MVP 우선순위

1. 워치 수동 SOS → 서버 → 보호자 Push/지도 표시
2. 규칙 기반 낙상 감지와 사용자 상태 확인
3. 자동 SOS와 안전 이벤트 기록
4. 안전구역 설정·이탈·재진입
5. 보호자 귀가 요청과 워치 귀가 안내
6. 실제 센서 데이터 수집 및 오탐률 평가

AI 낙상 분류, 이상 이동 탐지, 미착용 감지는 기본 MVP 이후 진행합니다.

```text
├── docs/               # 프로젝트 명세와 공통 계약

```

## 개발 시작 순서

1. `docs/API_CONTRACT.md`의 이벤트 및 API 이름을 세 파트가 함께 확정합니다.
2. 각 모듈의 패키지명, SDK 버전, 지도 SDK를 결정합니다.
3. 수동 SOS 수직 흐름을 실제 기기에서 먼저 완성합니다.
4. 낙상·안전구역·귀가 기능을 순서대로 연결합니다.
5. `docs/DEMO_SCENARIOS.md` 기준으로 통합 시연을 반복 검증합니다.

## 프로젝트 원칙

- 의료 진단이나 119 자동 신고 시스템이 아닙니다.
- 위치와 원시 센서 데이터는 필요한 범위에서만 수집·보관합니다.
- 운영 환경에서는 가능한 한 워치에서 센서를 판정하고 결과 이벤트만 전송합니다.
- 고령자·인지저하 사용자를 고려해 한 화면의 핵심 행동을 1~2개로 제한합니다.

협업 방법은 [CONTRIBUTING.md](CONTRIBUTING.md), 전체 구조는 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)를 참고하세요.
